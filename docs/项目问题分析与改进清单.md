## P0 — 正确性与并发

### ISSUE-001 扫描结束后未等待异步聚合，结果可能不完整

| 字段 | 内容 |
|------|------|
| **状态** | `已解决` |
| **位置** | `Sources/StringScannerCore/Core.swift`（`scanProject` → `concurrentPerform` 后立即 `outputResults`）；`Sources/StringScanner/ScannerViewModel.swift`（同样在 `concurrentPerform` 结束后立刻 `outputResults`） |
| **现象** | 每个文件在 `queue.async(flags: .barrier)` 中追加 `allStrings`，主流程不等待这些 block 执行完毕就排序/输出。CLI 的 `getScanResults()` 与 GUI 的 `results` 在文件多或磁盘慢时可能**漏掉部分字符串**。 |
| **解决方案** | 使用 `DispatchGroup`：每个文件扫描 `enter`，barrier 追加完成后 `leave`；`concurrentPerform` 返回后 `group.wait()`（或 `await`）再输出。更优：将「枚举 + 并行解析 + 聚合」封装进 `ProjectScanner` 的 async API，用 actor 持有结果数组，避免手写 barrier。 |
| **验证** | 对大仓库多次扫描同一目录，对比字符串总数与 golden 文件；单元测试 mock 慢速 barrier 延迟。 |

### ISSUE-002 GUI 进度计数 `processedFiles` 存在数据竞争

| 字段 | 内容 |
|------|------|
| **状态** | `已解决` |
| **位置** | `Sources/StringScanner/ScannerViewModel.swift` 约 68–81 行 |
| **现象** | `processedFiles += 1` 在 `DispatchQueue.concurrentPerform` 的多个线程中无同步修改，属于未定义行为；进度条可能抖动、不准，在 Swift 6 严格并发下可能触发运行时问题。 |
| **解决方案** | 用 `OSAllocatedUnfairLock` / `NSLock` / `ManagedAtomic<Int>` 保护计数；或用 `DispatchGroup` + 每完成一文件在主线程更新进度（接受轻微调度开销）。 |
| **验证** | Thread Sanitizer 下跑 GUI 扫描；或 stress test 小文件数千个。 |

---

### ISSUE-003 除零导致进度为 NaN

| 字段 | 内容 |
|------|------|
| **状态** | `已解决` |
| **位置** | `Sources/StringScanner/ScannerViewModel.swift` 约 65–80 行 |
| **现象** | 所选目录下无 `.swift`/`.m`/`.h` 文件时 `totalFiles == 0`，`Double(processedFiles) / Double(totalFiles)` 为 **NaN**，`ProgressView` 表现异常。 |
| **解决方案** | 扫描前若 `files.isEmpty`，主线程设置 `errorMessage`（或友好提示）、`progress = 0`、`isScanning = false` 并 return；否则用 `max(totalFiles, 1)` 仅作分母保护（仍应单独处理空目录 UX）。 |
| **验证** | 选择仅含 `README.md` 的空 Swift 工程目录。 |

## P1 — 功能与架构

### ISSUE-004 核心业务逻辑重复，GUI 未使用 `ProjectScanner`

| 字段 | 内容 |
|------|------|
| **状态** | `已解决` |
| **位置** | `ScannerViewModel` 与 `ProjectScanner` / `StringVisitor` |
| **现象** | `isValidFile`、`scanFile`、排序逻辑与 Core 几乎完全复制；`private let scanner = ProjectScanner()` **从未调用**。后续修 bug 容易只改一侧。 |
| **解决方案** | 扩展 `ProjectScanner`：支持进度回调、`@Sendable` 错误回调、可选「不写 stdout JSON」模式；ViewModel 只负责 UI 状态与调用 Core。删除 ViewModel 中重复的 SwiftSyntax 依赖。 |
| **验证** | 单测只测 Core；GUI 与 CLI 集成测各跑一遍。 |

### ISSUE-005 宣称支持 Objective-C（`.m`/`.h`），实际仅 SwiftSyntax 解析

| 字段 | 内容 |
|------|------|
| **状态** | `未解决` |
| **位置** | `isValidFile` 扩展名列表 + `Parser.parse`（Swift 解析器） |
| **现象** | `.m`/`.h` 会进入扫描队列，但 Swift 解析器对 ObjC 源码通常**无法**提取 `@"..."` 等字面量；实测对简单 `.h` **无报错、无结果**（静默失败）。与产品描述不符。 |
| **解决方案** | **方案 A（诚实收缩）**：仅支持 `.swift`，文档与 UI 文案同步。**方案 B（补能力）**：对 `.m`/`.h` 走独立管线（正则/Clang AST/轻量 ObjC 词法分析），与 Swift 结果合并。 |
| **验证** |  fixture 含 `NSLocalizedString(@"key", nil)` 的 `.m` 文件应出现在结果中且 `isLocalized == true`。 |

---

### ISSUE-006 本地化识别仅覆盖 `NSLocalizedString`

| 字段 | 内容 |
|------|------|
| **状态** | `未解决` |
| **位置** | `StringVisitor.isInLocalizationContext` |
| **现象** | 未识别 Swift 5+ 的 `String(localized:)`、`LocalizedStringKey`、`Text("key")`（SwiftUI）、`NSLocalizedString` 的 Swift 重载、`String(localized:comment:)`、自定义 L10n 包装等，易**误报未本地化**。 |
| **解决方案** | 扩展语法树判断：父节点为特定 `FunctionCallExpr` / `MacroExpansion`；维护可配置「本地化函数名列表」；可选读取 `Localizable.strings` / `.xcstrings` 做 key 交叉验证。 |
| **验证** | 快照测试：每种 API 各一条 fixture。 |

---

### ISSUE-007 正则字面量被当作普通字符串收集

| 字段 | 内容 |
|------|------|
| **状态** | `未解决` |
| **位置** | `StringVisitor.visit(_ node: RegexLiteralExprSyntax)` |
| **现象** | i18n 审计场景下，regex 模式通常**不是**待翻译文案，会污染结果集。 |
| **解决方案** | 默认跳过 regex 字面量，或增加 CLI/GUI 开关 `--include-regex`；若保留，增加 `kind: "regex"` 字段与 UI 筛选。 |
| **验证** | 含 `#/pattern/#` 的文件不应出现在默认导出中。 |

### ISSUE-008 会扫描 `Package.swift` 等构建清单中的字符串

| 字段 | 内容 |
|------|------|
| **状态** | `未解决` |
| **位置** | `isValidFile` 仅按扩展名过滤 |
| **现象** | SPM 项目的 `Package.swift` 中产品名、依赖 URL 等会进入结果，干扰「应用源码 i18n」分析。 |

### ISSUE-009 CLI 同时向 stdout 写 JSON 又写 `string_scan_results.json`

| 字段 | 内容 |
|------|------|
| **状态** | `未解决` |
| **位置** | `ProjectScanner.outputResults()` + `CommandLineTool.main()` |
| **现象** | 管道/脚本若只期望文件或只期望 stdout，会被**双份输出**干扰；`scanProject` 内 `print(jsonString)` 与 CLI 写文件内容重复。 |
| **解决方案** | 拆分 API：`scanProject(..., output: .stdout | .file(URL) | .silent)`；CLI 用 `--format json --output path` 或 `--stdout-only`。 |
| **验证** | `stringscanner-cli . > out.json` 与文件模式互斥行为符合帮助文档。 |
